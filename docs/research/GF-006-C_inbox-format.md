# 網站訂單進遊戲：Inbox 與匯入碼格式草案（GF-006-C）

- 撰寫：claude-addon，2026-11-23。**草案**，契約由 claude-pm 定稿（放進 `docs/contracts/`）。
- 依據：規格 `GF-006_crafting-orders_v1.0.md` R-9.4（第 1.5 版）、設計文件 `GF-006-A_crafting-orders.md` §4f、D-018 的五個限制、savedvariables §crafting（契約 v1.4）。
- 讀者：claude-sync（GF Sync 寫 `GreenFangToolkit_Inbox`）、GearBot（網站的待處理清單 API 與簽章）、claude-pm（定稿）。
- 狀態：AddOn 的解析器已照本檔實作在 `addon/GreenFangToolkit/WebOrders.lua`，**全部未實機驗證**。

---

## 1. 整體流程

1. 網站或 Discord 建立訂單 → 網站把它放進該公會的「待處理清單」。
2. GF Sync 定時向網站要清單（裝置授權），**驗證網站簽章**；不通過就不寫（D-018 第 2 點）。
3. GF Sync 把清單原樣（網站給的字串）寫進 `Interface/AddOns/GreenFangToolkit_Inbox/Inbox.lua`。
4. 工具箱登入或 `/reload` 時讀這個字串，用自己的解析器檢查，通過的網站單寫成**客人的 `M` 記錄**，再用 `GFTKO` 轉傳給公會裡其他有裝工具箱的人（沒裝 GF Sync 的人也收得到）。
5. 沒有人裝 GF Sync、或急著要：在網站複製「匯入碼」，在「訂單」頁按 📋 貼上。匯入碼和 Inbox 的字串**完全相同**，用同一個解析器。
6. 之後接單、交付、結案都在遊戲內走 `W`／`J`；有人登出時 GF Sync 上傳 `crafting`，網站依 `id` 合併（upload-api v1.4 §3 第 10 點）。

**為什麼由網站產生字串、GF Sync 原樣寫**：簽章是網站對這個字串簽的，GF Sync 驗證後不改內容，AddOn 讀到的就是網站簽過的那一份；匯入碼也是同一個字串，所以兩條路完全一樣。

## 2. `Inbox.lua`（D-018 第 1 點）

整個檔案**只有一行**：

```lua
GreenFangToolkit_Inbox = "GFIN1~..."
```

- 引號裡的字串只允許**可列印 ASCII**（0x20～0x7E），而且**不會有 `"` 和 `\`**（格式本身不用這兩個字元；網站產生時保證不出現，GF Sync 寫入前再檢查一次，出現就不寫）。所以 GF Sync 不需要做任何 Lua 轉碼，直接把字串放進引號。
- 不能有換行、Tab、`]]`、`--` 以外的任何 Lua 語法（實際上只要遵守上一點就不會有）。
- GF Sync 寫入後要自己讀回比對：檔案內容必須完全等於 `GreenFangToolkit_Inbox = "` + 字串 + `"` + 換行（`\n` 或 `\r\n`），不符就刪掉暫存檔、不改名（D-018 第 4 點：先寫暫存檔再改名）。
- 大小上限：**整個字串 65,536 bytes**、**最多 200 張網站單**（D-018 第 4 點）。網站超過時只放最新的 200 張（依 §3 的 `ut`）。
- 沒有網站單時：寫 `GFIN1~<sum>~<sig>~H;...`（只有表頭、0 張），**不要刪檔**，讓工具箱知道「清單是空的」而不是「沒有 Inbox」。

## 3. 字串格式（Inbox 和匯入碼共用）

```
GFIN1~<sum>~<sig>~H;<表頭欄位>~C;<客人欄位>~O;<訂單欄位>~O;...~C;...~O;...
```

- 用 `~` 分成幾段，第 1 段固定是版本 `GFIN1`。**不認得的版本整份略過**（D-018 第 3 點）。
- 第 2 段 `<sum>`：雜湊（§3d），AddOn 用它判斷字串沒有被截斷或寫壞。
- 第 3 段 `<sig>`：網站的簽章（§6），**AddOn 不驗證**，只要求它存在而且只有 `[A-Za-z0-9_-]`（base64url，不補 `=`），長度 1～200。GF Sync 驗證這個簽章。
- 第 4 段開始是記錄，每段以 `H;`、`C;`、`O;` 開頭：
  - `H` 表頭：剛好一個，在第 4 段。
  - `C` 客人：之後的 `O` 都屬於這位客人，直到下一個 `C`。
  - `O` 訂單：一張網站單。
- 每段內是 `;` 分隔的 `key=value`。**不認得的 key 忽略**（給之後的版本加欄位），但不儲存、不轉傳。同一段內同一個 key 出現兩次：整段不合格。

### 3a. `H` 表頭

| key | 必填 | 值 | 檢查 |
|---|---|---|---|
| `realm` | 是 | 伺服器名稱，**百分比轉碼**（§3c） | 必須等於玩家目前的伺服器（`GetRealmName`），否則整份略過（`other-realm`） |
| `guild` | 是 | 公會名稱，百分比轉碼 | 必須等於玩家目前的公會而且是目標公會，否則整份略過（`other-guild`） |
| `at` | 是 | 網站產生這份清單的伺服器時間（Unix 秒） | 不晚於現在 + 10 分鐘；早於 30 天前整份略過（`too-old`） |
| `n` | 是 | 訂單張數 | 必須等於後面 `O` 的數量，0～200 |

### 3b. `C` 客人、`O` 訂單

`C`：

| key | 必填 | 值 | 檢查 |
|---|---|---|---|
| `cu` | 是 | 客人 GUID（`Player-<數字>-<16 進位>`） | 必須在玩家看到的公會名冊上，否則這位客人的單全部略過（`not-member`） |
| `t` | 是 | 這位客人的網站單**整組**的修改時間（Unix 秒） | 網站在這位客人任何一張網站單新增、修改、取消、移出清單時都要往後推；AddOn 拿它當 `M` 記錄的時間 `t`（同樣內容的清單，誰匯入結果都一樣） |

`O`（對應 savedvariables §crafting 的 `w`，`src = "w"`）：

| key | 必填 | 值 | 對應 `w` | 檢查 |
|---|---|---|---|---|
| `id` | 是 | `w` 開頭，只有 `[0-9a-z.]`，2～64 字元 | `id` | 格式不對這張略過（`bad-id`） |
| `cr` | 是 | 建立時間 | `created` | 早於 30 天前略過（`too-old`）；晚於現在 + 10 分鐘略過 |
| `cf` | 是 | `*`（公會單）或工匠 GUID | `crafter` | GUID 必須在名冊上（`not-member`） |
| `rc` | 是 | 配方 ID | `recipe` | 1～9,999,999 |
| `it` | 否 | 成品物品 ID | `item` | 1～9,999,999 |
| `sk` | 否 | 專業 skillLineID | （遊戲內用） | 1～9,999 |
| `q` | 是 | 成品數量 | `qty` | 1～1,000 |
| `m` | 否 | 客人出的材料 `物品ID*數量+物品ID*數量` | `mats` | 最多 12 種；物品 ID 1～9,999,999，數量 1～10,000 |
| `fe` | 是 | 工錢（銅） | `fee` | 0～1,000,000,000 |
| `fq` | 否 | 下單時工匠的報價；**沒填就不寫** | `feeQuoted` | 同上 |
| `qt` | 否 | 材料估價 | `quote` | 同上 |
| `st` | 是 | `open` 或 `cancel`（網站那邊取消） | `cst` | 其他值這張略過 |
| `sa` | 是 | `st` 的時間 | `closedAt`（取消時） | 數字 |

- 不放名字、帳號、信箱、備註或任何自由文字（D-018 第 4 點；`note` 第二版再定）。`ext`（網站參考號）不放進字串。
- 一位客人最多 30 張（和遊戲內 `W` 一樣）；超過的那位客人整組略過（`too-many`）。
- **網站那邊的取消**：`st=cancel` 加 `sa`。遊戲內視為「網站取消」（`closedBy = "web"`），和客人、工匠的結案一樣「最早的結案為準」。
- 網站單在清單裡要留到**結案後 7 天**，之後才移出（和遊戲內的保留時間一樣）。移出時記得推 `C.t`。

### 3c. 轉碼

- `realm`、`guild` 用**百分比轉碼**：UTF-8 的每個 byte，只要不是 `[A-Za-z0-9._-]`，就寫成 `%XX`（大寫 16 進位）。空白也轉（`%20`）。
- 其他欄位本來就只有 `[A-Za-z0-9*+.-]`，**不轉碼**；出現其他字元的欄位整段不合格。
- 所以整個字串只會出現 `[A-Za-z0-9*+.%_;=~-]`，絕不會有引號、反斜線、空白、換行。

### 3d. 雜湊 `<sum>`

- 對象：第 4 段開始到字串結尾（也就是 `H;` 開頭那一段起，含中間的 `~`）。
- 算法（和工具箱 `Share.hash` 相同，任何語言幾行就能寫）：

```
h = (len(s) mod 16777213)
for each byte b in s: h = (h * 31 + b) mod 16777213
sum = h 寫成小寫 36 進位（0-9a-z），不補零
```

- 不符：整份略過（`bad-sum`）。這只是防截斷和寫壞，**不是防偽**（防偽靠 GF Sync 驗網站簽章；匯入碼依 D-013 第 3 點不假設有人送假資料）。

### 3e. 範例（假資料）

```
GFIN1~<sum>~c2lnbmF0dXJl~H;realm=%E6%B8%AC%E8%A9%A6%E4%BC%BA%E6%9C%8D%E5%99%A8;guild=<百分比轉碼>;at=1763900000;n=2~C;cu=Player-0000-0000000B;t=1763899000~O;id=w12;cr=1763890000;cf=*;rc=2660;it=2862;sk=164;q=5;m=2835*5;fe=500;st=open;sa=1763890000~O;id=w13;cr=1763891000;cf=Player-0000-0000000C;rc=2661;q=1;fe=0;fq=0;st=cancel;sa=1763899000
```

## 4. 匯入碼

- **就是 §3 的字串本身**。網站的訂單頁顯示它，旁邊一個「複製」按鈕。
- 網站顯示時可以每 80 個字元換行；AddOn 貼上時先**去掉所有空白和換行**再解析。
- 只有 ASCII，可以重複貼：同一張單（同 `id`、同 `C.t`）貼第二次結果不變（`M` 記錄的時間和雜湊都一樣）；網站之後改了，新的匯入碼 `C.t` 較新，會蓋掉舊的。
- 匯入碼可以只放**一位客人的一張單**（`n=1`），網站不必每次給整份清單。注意：這時 `C.t` 仍然要是那位客人整組的修改時間，而且 `C` 底下要列出那位客人**所有**仍在清單裡的網站單；不然較新的 `C.t` 會讓 AddOn 以為其他單被移出了。若網站不想這樣做，請改成匯入碼一律給整份清單（建議，比較單純）。
- 長度上限同 Inbox（65,536 bytes）；遊戲內的輸入框實際上能貼的長度未查證，所以建議網站的匯入碼**只放那位客人的網站單**（通常幾百 bytes）。

## 5. `GreenFangToolkit_Inbox` 的 `.toc`（固定內容）

GF Sync 每次檢查，不同就還原（D-018 第 1 點）。內容只有這幾行：

```
## Interface: 16001
## Title: GreenFangToolkit Inbox
## Notes: Data for GreenFangToolkit. Written by GF Sync.
## LoadOnDemand: 1
Inbox.lua
```

- **`LoadOnDemand` 在 16001 能不能用未查證**，兩種情況：
  - **可以用（A，預設）**：遊戲啟動時只登記這個 AddOn、不載入；工具箱在登入後用 `C_AddOns.LoadAddOn("GreenFangToolkit_Inbox")`（沒有的話用舊名 `LoadAddOn`）載入並讀全域變數。`/reload` 會再讀一次檔案。
  - **不能用（B）**：拿掉 `## LoadOnDemand: 1` 那一行，變成一般 AddOn，遊戲啟動（或 `/reload`）時就載入。工具箱在 `PLAYER_LOGIN` 時讀全域變數。
  - 工具箱兩種都支援：先看 `GreenFangToolkit_Inbox` 全域變數有沒有值；沒有才呼叫 `LoadAddOn`。實機查證後由 claude-pm 決定 GF Sync 寫哪一種。
- **資料夾要在遊戲啟動前就存在**：遊戲只在啟動時掃描 AddOn 資料夾。GF Sync 安裝（或第一次執行）時就建立資料夾、`.toc` 和空清單的 `Inbox.lua`；之後只改 `Inbox.lua` 的內容。
- 玩家可能在 AddOn 清單裡停用它；停用時工具箱讀不到，等同沒有 Inbox（只顯示在「同步與診斷」）。

## 6. 安全性檢查清單（AddOn）

- □ **絕不執行內容**：不用 `loadstring`、`load`、`RunScript`、`dofile`；只讀全域變數 `GreenFangToolkit_Inbox`，而且只接受字串型別（其他型別整份略過）。
- □ 讀之前先檢查長度（≤ 65,536 bytes）和字元集（§3c）；不符整份略過。
- □ 版本 `GFIN1`；雜湊相符；表頭只有一個、在第 4 段；`n` 和 `O` 數量一致。
- □ **只收目標公會、同伺服器**：`H.realm`、`H.guild` 對不上整份略過；玩家不在目標公會時不讀。
- □ 客人、指定工匠都必須在玩家看到的公會名冊上。
- □ 每個數字欄位：只有數字、在 §3b 的範圍內。
- □ `id` 必須 `w` 開頭、只有 `[0-9a-z.]`；遊戲建立的單（`g` 開頭）絕不會被網站單蓋掉。
- □ **超過 30 天的不收**：`H.at`、`O.cr` 早於 30 天前；晚於現在 + 10 分鐘也不收。
- □ 不認得的 key 忽略、不儲存；重複的 key 整段不合格。
- □ 一位客人最多 30 張、一份最多 200 張。
- □ 讀完只寫成 `M` 記錄（作者 = 客人），不改玩家自己的 `W`／`J`；客人本人對網站單按按鈕時，才把那張單複製進自己的 `W`。
- □ 每次讀取的結果（時間、匯入幾張、略過幾張和原因）只顯示在「同步與診斷」。
- □ Inbox AddOn 不存在、被停用、載入失敗、全域變數是空的：什麼都不做，不出錯，診斷頁寫「沒有 Inbox」。

## 7. 要網站提供什麼（GearBot；只列需求，claude-pm 轉交）

1. **建立網站單**（第 1.5 版）：欄位同 §3b；`id` 用 `w` 開頭（例如 `w` + 網站訂單號的 36 進位）。網站帳號 ID、網站參考號存在網站上，不放進字串。
2. **待處理清單 API**（給 GF Sync，裝置授權）：
   - 依公會回傳 §3 的完整字串（網站產生、網站簽章），以及產生時間。
   - 內容：這個公會所有「進行中、或結案 7 天內」的網站單，依客人分組；每位客人的 `C.t` 照 §3b 的規則維護。
   - 支援 `If-None-Match` 或 `since`，沒變化時回 304，GF Sync 就不改檔案。
3. **簽章**：
   - 網站用自己的私鑰對**整個字串去掉第 3 段（`<sig>`）之後的內容**簽章，建議 Ed25519，簽章用 base64url（不補 `=`）放進第 3 段。
   - 簽的內容：`GFIN1~<sum>~` + 第 4 段起的內容（也就是把第 3 段和它後面的 `~` 拿掉）。
   - 公鑰內建在 GF Sync；換鑰匙時 GF Sync 要能同時接受新舊兩把一段時間。
4. **匯入碼**：網站單的頁面顯示 §4 的字串和「複製」按鈕。
5. **合併上傳**：網站單在遊戲內產生的 `W`／`J` 照 upload-api v1.4 §3 第 10 點合併；網站自己的那一份（取消）也照 `recordedAt`（= `C.t`）比新舊。

## 8. 要 GF Sync 做什麼（claude-sync）

1. 定時（例如每 10 分鐘，遊戲開著或關著都可以）向 §7.2 的 API 要清單。
2. 驗證網站簽章（§7.3）；不通過、字串含 `"` 或 `\`、超過 65,536 bytes：不寫，記在 GF Sync 自己的狀態裡。
3. 只寫 `Interface/AddOns/GreenFangToolkit_Inbox/` 底下的 `GreenFangToolkit_Inbox.toc`（§5 固定內容）和 `Inbox.lua`（§2 一行）；先寫暫存檔、讀回比對、再改名。
4. 絕不碰 `WTF/`，不寫其他檔案或資料夾（D-018 第 5 點）。
5. 遊戲開著時改了檔案：遊戲要等下次 `/reload` 或登入才讀得到，GF Sync 不需要通知遊戲。
6. 玩家解除安裝 GF Sync 時，連同 `GreenFangToolkit_Inbox` 資料夾一起移除。

## 9. 未查證（16001）

- `LoadOnDemand` 和 `C_AddOns.LoadAddOn`／`LoadAddOn` 的行為、回傳值（§5）。
- 一般 AddOn 的全域字串在 `PLAYER_LOGIN` 時是否已經設好（應該是，所有 AddOn 都在 `PLAYER_LOGIN` 前載入）。
- 遊戲內多行輸入框能貼多長的字串（§4）。
